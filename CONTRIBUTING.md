# Contributing

Contributions that improve safe, accurate learning materials are welcome. Open an issue to suggest a correction, add context, or clarify a remediation before making a larger change.

## Good contributions

- Cite authoritative, current sources for technical changes.
- Distinguish observed behavior from interpretation and severity judgment.
- Keep practical testing examples inside the local, intentionally vulnerable Juice Shop lab.
- Explain remediations at the root-cause level and note version assumptions.
- Keep prose concise and link related findings rather than duplicating them.

## Do not include

- The source report PDF or its identifying front page.
- Credentials, tokens, hashes, private user records, or recovered passwords.
- Screenshots containing session data or personal information.
- Instructions for targeting systems outside the explicitly authorized lab.

Before submitting, check local Markdown links, scan for secrets and identifying material, and run `git diff --check`. No blanket license is granted for report-derived text or third-party material.
